# Architecture Review: Sparse Mixture-of-Experts Decoder on a Single-GPU Desktop Workstation

## 1. Scope and Classification of Evidence

Before any architectural conclusion is drawn, every quantitative claim in the project note must be tagged by its epistemic status. This separation prevents a simulated hit-rate from being mistaken for a measured throughput and keeps the review honest about what the hardware has actually demonstrated.

**Confirmed measurements (already obtained on the target workstation):**
- Each expert occupies approximately 2.76 MB of device memory (three quantized affine matrices).
- The GPU's usable memory accommodates only a strict subset of the 48 × 512 = 24,576 possible layer-expert pairs.
- Three execution modes exist and have been profiled in isolation: (a) expert resident on GPU, (b) expert copied from pinned host memory then executed on GPU, (c) expert executed on CPU workers with only activation and output crossing PCIe.
- The transfer-cost curve and the CPU-execution-cost curve cross as a function of the number of missing experts per layer, confirming that no single global routing policy is optimal.
- GPU compute, host-to-device (H2D) promotion, and CPU expert work can overlap in wall-clock time (measured via CUDA events and CPU thread timestamps).

**Simulated results (produced by software models, not yet validated end-to-end on hardware):**
- A prior synthetic cache study reported that an aggregate cache near 8 GB could reach roughly 60 % hit rate. Critically, this study used synthetic router outputs, not real per-token top-10 selections.
- The present study simulates several cache-eviction policies (LRU, LFU, FIFO, and a reuse-distance-aware variant) without future knowledge, using captured real top-10 IDs and normalized weights.

**Projected results (extrapolated or analytically estimated, not yet measured):**
- The 48-layer aggregate memory footprint of all experts is approximately 24,576 × 2.76 MB ≈ 67.8 GB, far exceeding any consumer GPU's VRAM (typically 8–24 GB).
- Expected per-token latency under the proposed dynamic hybrid policy, derived from the overlap measurements and simulated hit rates, is projected but not yet confirmed in a full 48-layer forward pass.

**Assumptions (stated or implicit in the note):**
- The PCIe link is the sole host-device interconnect; no NVLink or CXL path exists.
- Quantization is fixed (the 2.76 MB figure bakes in the chosen bit-width); no further compression is assumed.
- Router outputs are deterministic given the input token sequence; no stochastic top-k sampling
