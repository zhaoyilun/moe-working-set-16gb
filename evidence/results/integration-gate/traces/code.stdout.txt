# Event-Driven Sparse MoE Expert-Cache Simulator

## 1. Design Overview

This simulator models the runtime behaviour of a 48-layer sparse Mixture-of-Experts (MoE) transformer where each layer contains 512 experts and each token activates exactly 10 experts per layer (top-10 routing). The GPU holds a byte-capacity cache of expert weights; on a miss the simulator must decide whether to transfer the expert from host (CPU) memory to the GPU (H2D) or to compute on the CPU, using a cost-aware model that accounts for PCIe bandwidth, compute overlap, and expert size.

The simulator is **event-driven**: a priority queue of timestamped events (token arrivals, cache lookups, H2D transfers, compute completions) is processed in causal order. This lets us model pipelining, overlap, and contention without a fixed-tick loop.

### Complexity Summary

| Operation | Complexity |
|---|---|
| Cache lookup / insert / evict (LRU, LFU, CLOCK) | O(1) amortised |
| Static-hot + dynamic eviction | O(1) amortised |
| Frequency-gated admission check | O(1) |
| Event dispatch (heap) | O(log E) per event |
| Full trace replay (T tokens × L layers × K experts) | O(T·L·K·log E) |
| Property-test invariant checks | O(1) per event |

where *E* is the number of cached experts, *T* tokens, *L* = 48 layers, *K* = 10 experts/token/layer.
